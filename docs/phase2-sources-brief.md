# Phase 2 — 出典カードを作る（エージェント向け指示書）

**成果物は `ledger/sources/<slug>.json` です。記事は1本も書きません。**

執筆エージェントが各自で一次情報を探し回ると、同じ論文・同じ公式ドキュメントを何度も取得します。
**ここで1回だけ集めて、執筆側は「もう決まった出典を読みに行くだけ」にします。**

---

## 0. 絶対に守ること

1. **本文の抜粋を保存しない。** 保存してよいのは **タイトル・URL・「何を裏付ける出典か」の1行**だけです。
   他人の著作物をリポジトリに溜め込まないため（[LICENSE.md](../LICENSE.md) 3項）
2. **URL は実在するものだけ。** 開いて中身を確認したものだけを載せます。**推測でパスを組み立てない**
   ★**「200 が返ること」を実在の証拠にしない（2026-08-22 追記・実害あり）。** 取得した本文に
   **カードに書こうとしているタイトルが実際に載っているか**まで確かめてください。
   `openreview.net/forum?id=H1gaxQgrg` を「Language Models are Unsupervised Multitask Learners」として
   登録したカードが1件あり、そのIDは別の論文のものでした（GPT-2 は OpenReview に出ていません）。
   URL は生きているので、リンク切れ検査では捕まりません
3. **許可リスト外のドメインは載せない。** `scripts/validate.py` の `SOURCE_ALLOWLIST` が唯一の真です。
   「良い解説だから」で他社教材・個人ブログ・問題集を入れない
4. **ブラウザ系のツールは使えません**（承認が要るため自動拒否されます）。`curl` を使ってください
5. **出典が見つからない概念は、空のカードを作らずスキップして報告する。** でっち上げない

## 1. 対象

`ledger/concepts.json` の全概念です。**`ledger/sources/<slug>.json` が既にあるものは飛ばしてください**（再実行できる形にしてあります）。

**1回の実行で最大25件**にしてください。全部やろうとすると途中で力尽きて、どこまでやったか分からなくなります。
25件終わったら、そこで報告して終了してください。**残りは次の実行が拾います。**

優先順位は `tier` の A → B → C、`optional: true` は最後です。

## 2. 出典の選び方

**1概念あたり2〜4件。** 多いほど良いわけではありません。**執筆者が読むのは全部です。**

| 概念の種類 | 一次情報として何を引くか |
|---|---|
| 手法・アーキテクチャ（Transformer, ResNet, Adam…） | **原論文**（arXiv / 学会）。「提案したのは誰か」が確定する |
| 実装・API（PyTorch の autograd, 正規化層…） | **公式ドキュメント**の該当ページ |
| 数学の基礎（エントロピー、KLダイバージェンス…） | 著者が公開している教科書、または該当を扱う論文 |
| 評価指標・慣行 | それを定義した論文、または公式ドキュメント |

**原論文が第一候補です。** サーベイ論文で代用しない（誰が何を提案したかがぼやけます）。

## 3. 出力の形

`ledger/sources/<slug>.json`:

```json
{
  "slug": "self-attention",
  "sources": [
    {
      "title": "Attention Is All You Need",
      "url": "https://arxiv.org/abs/1706.03762",
      "why": "Self-Attention と Multi-Head Attention の定義、スケーリング係数の根拠"
    }
  ]
}
```

- `why` は **120字以内**。**出典の要約ではなく「この出典で何が裏付けられるか」**を書きます
  - ✅ `"Scaled Dot-Product Attention の定義と √d_k で割る理由"`
  - ❌ `"Transformerを提案した有名な論文で、RNNを使わずにAttentionだけで..."` （要約になっている）
- `excerpt` / `content` / `body` のようなキーは**入れてはいけません**（検証で ERROR）

## 4. 終わったら必ず実行する

```bash
python3 scripts/validate_sources.py --check-links
```

**ERROR が0になるまで提出しないでください。** 特に `SOURCES_DOMAIN`（許可リスト外）と
`SOURCES_DEAD`（404）は、そのまま執筆に渡すと記事ごと落ちます。

## 5. 報告すること

1. 今回作ったカードの件数と、残り件数
2. **出典が見つからなかった概念**と、その理由。**これは人間が判断します**（許可リストを広げるか、概念を統合するか）
3. 許可リストに足したいドメインの提案があれば、その根拠（なぜ一次情報と言えるか）

---

| 起きたこと | どうするか |
|---|---|
| 原論文が arXiv に無い（学会のみ・有料） | `doi.org` / `dl.acm.org` / `aclanthology.org` を試す。無ければ公式ドキュメントで代用し、報告に書く |
| 概念が複数の論文にまたがる | 2〜4件に収める。**入れすぎない**。執筆者が読む量が増えるだけです |
| 許可リスト外にしか出典が無い | **載せない。** 報告の2に書いて人間の判断を待つ |
