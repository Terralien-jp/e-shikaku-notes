# Phase 0 — 概念台帳を作る（エージェント向け指示書）

**成果物は `ledger/concepts.json` 1本です。** 記事は1本も書きません。

この台帳が「何を書くべきか」の唯一の真になります。ここが漏れると、そのぶん永久に書かれません。
逆にここに嘘（実在しない項目）が入ると、そのぶん無駄なノートが書かれます。**慎重にやってください。**

---

## 0. 絶対に守ること

1. **公式シラバスを実際に取得して読む。** 記憶で書かない。E資格のシラバスは改訂されており、
   記憶にある版と現行版は違います
2. **シラバスの文言を1文字も転記しない。** これは著作物です。台帳に入れてよいのは
   **項目の識別子**と、**あなたが自分の言葉で付けた概念名**だけです
3. **取得できなかったら、そこで止めて報告する。** 推測で埋めない。
   「シラバスPDFが取得できなかった」という報告は失敗ではなく、正しい結果です
4. **試験問題・想定問題を作らない。** ここでは概念名を列挙するだけです

## 1. 入力

現行シラバスは **E2026#2〜** です（1つ前は E2024#2〜）。

- 一覧ページ: <https://www.jdla.org/certificate/engineer/>
- このページに「E資格の試験出題範囲（シラバス）E2026#2〜」へのリンクがあります。**そこから辿ってください**

**PDFの直リンクURLを推測して組み立てないでください。** 一覧ページから機械的に辿ります。

### 取得手順（2026-08-18 に動作確認済み）

★**ブラウザ系のツールは使えません**（承認が要るため自動で拒否されます）。**`curl` を使ってください。**

配布は WordPress の download-manager プラグイン経由で、ダウンロードURLは
ページ内の `data-downloadurl` 属性に入っています。**そこから取り出します**（組み立てない）。

```bash
PAGE='https://www.jdla.org/certificate/engineer/'
# 1. 一覧ページから「E2026#2〜」のシラバス配布ページのURLを取り出す
# 2. その配布ページを取得し、data-downloadurl 属性の値を抜く
curl -sL "$DOWNLOAD_PAGE" -o /tmp/jdla.html
DL=$(grep -oE 'data-downloadurl="[^"]*"' /tmp/jdla.html | head -1 | sed 's/data-downloadurl="//;s/"$//')
# 3. PDF を取得してテキスト化する
curl -sL "$DL" -o /tmp/syllabus.pdf
pdftotext -layout /tmp/syllabus.pdf /tmp/syllabus.txt
```

**期待される結果**（違ったら版が変わった可能性があるので報告してください）:
`/tmp/syllabus.pdf` は5ページの PDF、`/tmp/syllabus.txt` は約21,000字。
先頭に「E資格 試験出題範囲 (シラバス 2026)」「2026年8月試験（E2026#2）より適用」とあります。

`pdftotext` が無い場合は `python3 -c "import pypdf"` を試し、どちらも無ければ**そこで報告して終了**してください。

取得できない場合は、**何がどう失敗したかを書いて終了**してください。推測で埋めないこと。

## 2. やること

シラバスの項目を読み、**ノート1本の単位**に切り分けて `ledger/concepts.json` に並べます。

### 切り分けの粒度

**「1本のノートで説明が閉じるか」**で切ります。シラバスの見出しと1対1にする必要はありません。

| 良い切り方 | 理由 |
|---|---|
| `誤差逆伝播法` を1本 | 説明が閉じる。前提（連鎖律）は別ノートへリンクすればいい |
| `バッチ正規化` と `レイヤー正規化` を別々 | 使い分けが問われる。1本に混ぜると比較表が主役になって定義が薄まる |
| `活性化関数` を1本にまとめる | 個別に立てると各ノートが3行で終わる。**比較して初めて意味が出る**タイプ |

**迷ったら分けすぎない。** 400字も書くことがない概念は、親のノートの一部にしてください。
`tier: C` は「短くてよい」であって「無理に独立させる」ではありません。

### Tier の付け方

出題比重ではなく **「間違えたときに他へ波及するか」** で決めます。

- **A**: 崩れると周辺概念が全部崩れるもの（例: 誤差逆伝播、確率分布の基礎）
- **B**: 標準。単独で問われ、実装も伴うもの
- **C**: 単独で閉じ、暗記に近いもの（特定の引数仕様、用語の定義）

### `syllabus_refs` の入れ方

**項目を指す識別子だけ**を入れます。番号体系がシラバスにあればその番号、無ければ
**章・節の見出しを短い名詞句に圧縮したもの**（40字未満・句点を含まない）。

```json
"syllabus_refs": ["2.3", "2.4"]          // 番号があるならこれが一番よい
"syllabus_refs": ["深層学習-正則化"]      // 番号が無い場合
```

❌ `"syllabus_refs": ["正則化の手法について理解していること"]` — **これは転記です。ERROR になります**

## 3. 出力の形

```json
{
  "exam": "E資格",
  "ledger_status": "complete",
  "syllabus_version": "E2026#2",
  "syllabus_source": "https://www.jdla.org/certificate/engineer/",
  "areas": ["応用数学", "機械学習", "深層学習", "開発・運用環境"],
  "concepts": [
    {
      "slug": "backpropagation",
      "concept": "誤差逆伝播法",
      "area": "深層学習",
      "tier": "A",
      "syllabus_refs": ["3.2"],
      "status": "todo"
    }
  ]
}
```

- `status` は**全件 `todo`** で出してください（本文はまだ無いので）
- `ledger_status` は、シラバスを最後まで読み切れたら `complete`、
  一部しか読めなかったら `bootstrap` のままにして**どこが読めなかったかを報告**してください
- `areas` の4区分は固定です。増やさないでください
- 詳しいフィールド定義は [`ledger/SCHEMA.md`](../ledger/SCHEMA.md)

## 4. 終わったら必ず実行する

```bash
python3 scripts/validate_ledger.py
```

**ERROR が0になるまで提出しないでください。** このスクリプトは特に次を見ています。

| 検査 | 落ちる例 |
|---|---|
| `CONCEPT_TRANSCRIPT` | 概念名が文になっている・30字を超える → **シラバス転記の疑い** |
| `REFS_TRANSCRIPT` | `syllabus_refs` に本文らしき文字列 |
| `SLUG_FORMAT` / `SLUG_DUP` | slug の形式・重複 |
| `AREA` / `TIER` / `STATUS` | 値が規定外 |
| `AREA_COVERAGE` | どれかの区分が0件（＝取りこぼし） |

## 5. 報告すること

台帳と一緒に、以下を短く書いてください。**数字は実測値で**。

1. 概念の総数と、区分ごとの内訳
2. Tier A / B / C の件数
3. **迷った切り分け**（分けるか統合するか判断が割れたもの）を3〜5件。理由つき
4. **シラバスに項目はあるが、一次情報の許可リスト（`scripts/validate.py` の `SOURCE_ALLOWLIST`）
   では出典が確保できそうにないもの**。これは人間が判断します
5. 読めなかった箇所があればその範囲

## 想定していない事態への対応

| 起きたこと | どうするか |
|---|---|
| シラバスPDFが取得できない | **止めて報告。** 推測で埋めない |
| 現行版が E2026#2 ではなかった | **実際に見た版で作り、報告に書く。** この指示書のほうが古い可能性がある |
| 区分4つに収まらない項目があった | 一番近い区分に入れ、**報告の3に書く。** `areas` は勝手に増やさない |
| 概念数が想定（130〜160）から大きく外れた | **そのまま出す。** 数を合わせに行かない。外れた理由を報告に書く |
