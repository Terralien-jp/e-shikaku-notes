# E資格 学習ノート ライター規約

**あなたの成果物は `content/<slug>.md` 1本です。**
読者は**一度 E資格を取ったが手が動かなくなった中堅〜ベテランのエンジニア**で、もう一度受けるために読みます。
入門者向けではありません。**「知らない人に用語を教える」ではなく「知っている人が試験と実装で迷う場所を潰す」**のが仕事です。

## 0. 絶対に守ること（破ったら差し戻し）

1. **書く前に一次情報を読む。** 記憶で書かない。特に手法の提案年・元論文の主張・ライブラリの現行APIは間違えやすい
2. **出典は許可リストのドメインのみ**（`scripts/validate.py` の `SOURCE_ALLOWLIST`）。**他社の教材・問題集・個人ブログは参照も引用もしない**
3. **URL は実在するものだけ。** それらしいパスを組み立てない。開いて読んだものだけ `sources` に置く
4. **試験問題を書かない。** 過去問・想定問題の再現は1問もしない。`## 試験でどう問われるか` は**問われ方の型**を書く場所であって、問題を作る場所ではない
5. **JDLA シラバスの文言を転記しない。** 項目を参照して自分の言葉で書く
6. **全 H2 に視覚要素を1つ以上**（表 / `<div class="analogy">` / `<div class="caution">` / `<details class="recall">` / 数式ブロック / コードブロック）
7. **説教で締めない。** 「〜が重要です」「意識しましょう」は書かない。事実と判断基準を置いて終わる

## 1. 文体

- **ですます調。** 論文調（「〜である」）にしない
- 読者は同業。**基礎の説明に紙幅を使わない**（「行列とは」は要らない）
- 断定できることは断定する。「〜な場合もあります」の連発は情報量ゼロ
- 一人称・自分語りは不要。ここは記録ではなく**道具**

## 2. ファイルの形

```yaml
---
exam: E資格
concept: 誤差逆伝播法          # 表示名（日本語）
slug: backpropagation          # ファイル名と完全一致
tier: A                        # 台帳の指定をそのまま
area: 深層学習                 # 応用数学 / 機械学習 / 深層学習 / 開発・運用環境
summary: 一覧に出る1〜2文
updated: 2026-08-18
sources:
  - title: "ページ・論文のタイトル"
    url: https://arxiv.org/abs/...
---
```

**構成の見本: [`docs/example-note.md`](example-note.md)。迷ったらこれと同じ形にする**（分量は見本のほうが不足しています）。

### 本文の H2（この順・この見出し名で固定）

| # | 見出し | 中身 | A | B | C |
|---|---|---|---|---|---|
| 1 | `## ひとことで言うと` | 定義1〜2文＋`<div class="analogy">` の喩え | 必須 | 必須 | 必須 |
| 2 | `## なぜ必要か` | 何の不便を解いたか。前後の手法との関係 | 必須 | 必須 | 任意 |
| 3 | `## 仕組み` | 数式と導出の要点。**式は必ず記号の意味を添える** | 必須 | 必須 | 必須 |
| 4 | `## 試験でどう問われるか` | **問われ方／正解に寄る条件／引っかけ** の3列表 | 必須 | 必須 | 必須 |
| 5 | `## 実装で確かめる` | 実行できる短いコード。NumPy か PyTorch | 必須 | 必須 | 任意 |
| 6 | `## 取り違えやすいもの` | 似た手法との切り分け表 | 必須 | 必須 | 必須 |
| 7 | `## 想起チェック` | `<details class="recall">` で3〜4問（B は2〜3／C は1〜2） | 必須 | 必須 | 必須 |

**分量:** A = 1,800〜2,800字 / B = 900〜1,500字 / C = 400〜700字。

★**下限のほうが効きます。上限に収めるために説明を削らないでください。**
実測（2026-08-22）で、上限を気にして「重複を削る」方向に寄せたノートが下限を1,800字下回り、
書くべきことは揃っているのに**「なぜそうなるか」の一段が抜けた**形になりました。
上限は多少超えてよく、**下限を割るほうが不合格**です。基準は見本
[`content/backpropagation.md`](../content/backpropagation.md)（地の文で約2,100字）。

**ただし、字数を埋めるために薄い文を足さない。** 削るべきは重複であって説明ではありません。

## 3. 数式

- KaTeX 記法。インラインは `$...$`、ブロックは `$$...$$`。`\( \)` `\[ \]` は使わない
- ★**コマンドのバックスラッシュを落とさない。** `\mathbf{x}` を `mathbf{x}` と書いても KaTeX は英字列として通してしまい、読者の画面に `mathbf{x}` がそのまま出ます。**シェル経由でファイルを書くときに脱落しやすい**ので、書いたあと必ずファイルを読み直して確認すること（`\theta` がタブ文字に化ける事故も同じ原因）。`validate.py` の `MATH_ESCAPE` が検査します
- **記号を導入したら必ず意味を書く。** $\theta$ とだけ書いて何のパラメータか書かないのは不合格
- 導出は「途中式を全部書く」ではなく「**どこで何が効いたか**」がわかる粒度で

## 3-2. 囲み・想起チェックの中に書くとき（必読）

**`<div class="analogy">` `<div class="caution">` `<details class="recall">` の中身は、開きタグの直後に空行を入れないと Markdown も数式も解釈されません。**
CommonMark が生の HTML ブロックとして丸ごと通してしまうためで、見た目は `$\varepsilon$` のような生文字がそのままページに出ます。

```markdown
<details class="recall">
<summary>質問はここに（数式は使わない）</summary>

答え。ここは空行で区切ったので $\theta$ も表も効きます。

</details>
```

- 開きタグの直後・閉じタグの直前に**空行**を入れる
- `</summary>` の直後にも**空行**を入れる
- **`<summary>` の中に数式を書かない**（この行だけは常に生の HTML で、KaTeX が通らない）

`validate.py` が `RAW_HTML_TIGHT` / `MATH_IN_SUMMARY` で ERROR にします。

## 4. コード

- `content` に置くコードは**実際に実行されます**（CI が走らせる）
- 依存は `numpy` まで。PyTorch を使う場合や外部データが要る場合は ` ```python no-run ` を付ける
- **出力を本文に書くなら、実際に実行した出力を貼る。** それらしい数字を書かない
- 20行以内を目安に。動く最小の形が一番読まれる

## 5. 書き終えたら

```bash
python3 scripts/validate.py content/<slug>.md --check-code
```

**ERROR が0になるまで出さない。** WARN は内容を見て判断（`MATH_SKIP` はローカルに katex が無いだけなので無視してよい）。
