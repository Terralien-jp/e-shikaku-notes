## ひとことで言うと

確率的勾配降下法（SGD）は、全訓練データの勾配を毎回正確に求めず、ランダムに選んだサンプル（またはミニバッチ）から勾配を推定してパラメータを更新する方法です。3者の違いは名前よりも、**1回の更新に何サンプル使うか**で見ると迷いません。

<div class="analogy">

大きな荷物を運ぶとき、全員の意見を集めてから一歩進むのがバッチ、ひとりの意見だけで小刻みに進むのが確率的勾配降下、数人の意見を平均して進むのがミニバッチです。後ろ2つは一歩ごとの判断に揺れがある代わりに、全員を待つ時間を減らせます。

</div>

## なぜ必要か

訓練目的がサンプルごとの損失の平均なら、全データ $N$ 個で勾配を計算するバッチ法は正確です。しかし全データを評価するため重くなります。ランダムに $m$ 個だけ選べば、計算量を抑えられます。

サンプル数を増やしても勾配推定の標準誤差はおおむね $1/\sqrt{m}$ でしか減りません。この逓減がミニバッチを置く理由です。

| 方法 | 1回の更新に使うサンプル | 勾配の性質 |
|---|---:|---|
| バッチ勾配降下法 | 全訓練データ $N$ | 正確な訓練集合勾配 |
| 確率的勾配降下法 | 1 | 分散が大きい推定 |
| ミニバッチ法 | $1<m<N$ | 分散と計算量の折衷 |

## 仕組み

訓練例を $(x^{(i)},y^{(i)})$、モデルのパラメータを $\theta$、1例の損失を $L_i(\theta)$、ミニバッチのサンプル数を $m$ とします。ミニバッチ $B_k$ をランダムに選んだとき、平均勾配の推定値は次です。

$$
\hat{g}_k=\frac{1}{m}\sum_{i\in B_k}\nabla_\theta L_i(\theta_k)
$$

$\nabla_\theta L_i$ は例 $i$ の勾配、$\theta_k$ は更新 $k$ 回目のパラメータ、$B_k$ は選んだ集合です。更新式は

$$
\theta_{k+1}=\theta_k-\varepsilon_k\hat{g}_k
$$

となります。$\varepsilon_k$ は学習率です。$m=1$ なら確率的、$m=N$ ならバッチ、途中の $m$ ならミニバッチです。文献によって「SGD」をミニバッチを含む総称として使います。

小さい $m$ の勾配にはサンプリング由来のノイズが残ります。局所的な領域から動く方向や、過度な適合を抑える効果を持ちます。ただし分散が大きいほど不安定です。

学習率を固定したままにできるバッチ法と違い、SGDでは推定ノイズが極小点に近づいても消えません。そのため学習率を徐々に下げます。理論上の十分条件の一つは、$\varepsilon_k$ が次を満たすことです。

$$
\sum_{k=1}^{\infty}\varepsilon_k=\infty,\qquad
\sum_{k=1}^{\infty}\varepsilon_k^2<\infty
$$

前者は早く止まらない条件、後者はノイズの累積を抑える条件です。実務上は学習率を線形に減衰させます。初期値が大きすぎれば振動し、小さすぎれば進みが遅くなります。

ミニバッチ内の例は並列処理できますが、極端に小さいと演算資源を使い切れず、大きくするとメモリを消費します。バッチサイズは勾配の分散、メモリ容量、ハードウェア、1更新の時間の交点で決まります。

## 試験でどう問われるか

| 問われ方 | 正解に寄る条件 | 引っかけ |
|---|---|---|
| 3手法の比較 | 1更新に使うサンプル数を、全件・1件・その中間で区別する | 「ミニバッチは全データを使う」とする |
| 更新式の記号 | $\hat g_k$ は選んだ $m$ 例の勾配平均、$\varepsilon_k$ は学習率 | 勾配の符号を逆にして損失増加方向へ進める |
| バッチサイズを増やす効果 | 勾配推定は正確になるが、標準誤差の改善は $1/\sqrt m$ で逓減する | 計算量も同じ比率で効率化すると考える |
| ノイズと学習率 | 小バッチほど揺れが大きく、安定性のため学習率を下げる場合がある | ノイズは常に悪影響とする |
| 収束条件 | 学習率の総和は発散し、二乗和は収束する | 学習率を単に一定にすれば十分とする |
| 並列化 | ミニバッチ内の例を並列処理でき、メモリはバッチサイズに伴って増える | 大きくすれば無条件に速くなるとする |

## 実装で確かめる

`batch_size` を変えると、1回の更新で参照する例数と更新回数が変わります。

```python
import numpy as np

rng = np.random.default_rng(0)
x = rng.normal(size=(10, 2))
y = 2 * x[:, 0] - x[:, 1]

for batch_size in (10, 1, 4):
    theta = np.zeros(2)
    updates = 0
    for start in range(0, len(x), batch_size):
        xb, yb = x[start:start + batch_size], y[start:start + batch_size]
        error = xb @ theta - yb
        grad = 2 * xb.T @ error / len(xb)
        theta -= 0.1 * grad
        updates += 1
    print(batch_size, updates)
```

## 取り違えやすいもの

| 用語 | 切り分け |
|---|---|
| バッチ勾配降下法 | 全訓練データの勾配を使う決定論的な方法。更新ごとのサンプリングノイズはない |
| 確率的勾配降下法 | 1例だけを使う狭義の意味と、ミニバッチを含む広義の意味がある。文脈ではサンプル数を確認する |
| ミニバッチ勾配降下法 | 1例より多く全件より少ない集合の平均勾配を使う。深層学習で一般的な折衷 |
| モメンタム | 過去の勾配も使う拡張。バッチサイズを決める手法ではない |
| 適応的最適化 | パラメータごとに学習率を調整する別系統の手法。ここでは更新式の基本形までに留めます |

<details class="recall">
<summary>バッチ、確率的、ミニバッチの違いを何で分類するか</summary>

1回の更新に使うサンプル数です。全件ならバッチ、1件ならSGD、その中間ならミニバッチです。

</details>

<details class="recall">
<summary>ミニバッチの勾配推定値は何を平均しているか</summary>

選んだ集合 $B_k$ の各例の勾配を足し、サンプル数 $m$ で割っています。

</details>

<details class="recall">
<summary>SGDで学習率を減衰させる理由は何か</summary>

サンプリングによる勾配のノイズが、極小点に近づいても消えないからです。学習率を下げて更新の揺れを小さくします。

</details>
